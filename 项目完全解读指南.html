🧭 一、项目概览

1.1 这是什么项目？

火龙果智能温控系统是一个智能温度控制管理平台的登录/用户模块。它不是一个玩具项目，而是一个 具备生产级思维的演示系统，包含完整的登录认证、用户注册、角色权限管理功能。

核心亮点：

  • 零外部依赖的 HTTP 服务器 — 纯 JDK 内置 com.sun.net.httpserver 实现，不需要 Tomcat/Spring
  • 三种登录方式 — 账号密码、短信验证码、微信授权，覆盖主流认证场景
  • 双模式运行 — 本地模式（Java 后端 + 真实 HTTP）+ 演示模式（纯前端模拟，可部署 GitHub Pages）
  • 角色权限系统 — admin/user 双角色，管理员可查看/删除用户
  • 手写 JSON 序列化 — 不依赖 Jackson/Gson，理解底层原理
  • ConcurrentHashMap 内存存储 — 模拟数据库，理解并发安全
  • 现代化前端 — 粒子动画、3D 标签云、Chart.js 图表、响应式设计

☕ 四、后端核心模块详解

4.1 程序入口 — dragonThermLogin.java

这是整个后端的大脑。它决定程序以什么模式运行：

  • 无参数启动：调用 HttpServer.main(args)，启动 HTTP 服务器（默认 8080 端口）
  • 带端口号：如 9090，启动 HTTP 服务器在指定端口
  • console 模式：直接在命令行运行三种登录方式的测试，不启动服务器
💡 学习要点：这是典型的 Facade 模式——对外暴露简单的静态方法 dragonThermLogin(LoginRequest) 和 sendSmsCode(String)，内部委托给 LoginService 处理。

4.2 HTTP 服务器 — HttpServer.java

这是整个项目最核心、代码量最大的文件（709行）。它实现了一个完整的 HTTP 服务器，包括：

路由表

方法路径处理器功能
GET/ 或 /login.htmlserveStaticFile返回登录页面
GET/* (其他路径)serveStaticFile返回静态文件 (css/js/图片)
POST/api/sendSmshandleSendSms发送短信验证码
POST/api/loginhandleLogin用户登录
POST/api/registerhandleRegister用户注册
GET/api/admin/usershandleAdminListUsers管理员获取用户列表
DELETE/api/admin/usershandleAdminDeleteUser管理员删除用户

关键技术实现

  • 静态文件服务：resolveStaticRoot() 方法使用 4 级回退策略查找 web 目录——当前目录 → user.dir → classpath 向上遍历 → 兜底路径
  • 路径遍历防护：检查 .. 防止目录穿越攻击
  • 手写 JSON 解析：使用正则表达式 extractJsonField() 提取 JSON 字段，避免引入 Jackson/Gson
  • 手写 JSON 序列化：toJson(LoginResponse) 方法手动拼接 JSON 字符串
  • JSON 字符串转义：escapeJson() 处理反斜杠、引号、换行等特殊字符
  • Form/JSON 双格式兼容：请求体同时支持 application/json 和 application/x-www-form-urlencoded
  • Bearer Token 鉴权：从 Authorization 头提取 token，校验管理员权限

4.3 核心业务 — LoginService.java

包含所有业务逻辑，是整个系统的"心脏"：

数据存储（4 个 ConcurrentHashMap）

Map 名称KeyValue用途
PUGE_USER_MAP手机号 / "WECHAT_" + openIdPugeUser主用户表（模拟数据库）
USER_ID_MAPuserIdPugeUser用户ID快速索引
TOKEN_USER_MAPaccessToken (UUID)userIdToken → 用户映射

核心方法

  • login(LoginRequest) — 登录入口，按 loginType 分发到三种处理器
  • register(RegisterRequest) — 注册新用户，自动生成 userId，返回 token
  • handlePasswordLogin() — 查用户 → 验密码 → 发 token
  • handleSmsCodeLogin() — 验验证码 → 用户不存在则自动注册 → 发 token
  • handleWechatLogin() — 授权码换 OpenId(模拟) → 查微信用户 → 不存在则自动注册 → 发 token
  • generateToken() — 用 UUID.randomUUID() 生成唯一 token
  • getAllUsers() — 返回所有用户（管理员功能）
  • deleteUser(adminToken, phone) — 管理员删除用户（含多重保护：不能删自己、不能删管理员）
🔑 为什么用 ConcurrentHashMap？
HttpServer 使用默认线程池，意味着多个请求可能并发执行。
HashMap 在并发 put 时可能导致死循环或数据丢失。
ConcurrentHashMap 使用分段锁，保证线程安全的同时性能接近 HashMap。

4.4 短信验证码 — SmsCodeService.java

  • 验证码生成：Random.nextInt(1000000) → String.format("%06d") 生成 6 位数字
  • 防刷机制：同一手机号 60 秒内不能重复发送
  • 验证码生命周期：发送 → 未使用 → 校验通过 → 标记已使用 → 删除
  • 过期处理：超过 60 秒自动失效，提示重新获取
  • 隐私保护：maskPhone() 方法将 13546069966 显示为 135****9966
  • SmsCodeInfo 内部类：封装验证码 + 发送时间 + 使用状态

🔄 六、请求生命周期完整追踪

6.1 账号密码登录 — 完整流程

1
用户输入

在 login.html 的"账号登录"tab 中输入手机号 13546069966 和密码 123456

2
前端校验

login.js → buildPayload() → 校验手机号格式 → 校验密码非空 → 构建 {loginType:3, phone:"13546069966", password:"123456"}

3
发送请求

request('/api/login', 'POST', payload) → XHR → Content-Type: application/json

4
HTTP 服务器接收

HttpServer.handleRequest() → path="/api/login", method="POST" → handleLogin()

5
解析请求体

readRequestBody() → extractJsonField() 逐个提取字段 → 构建 LoginRequest 对象

6
参数校验

LoginRequest.validate() → PASSWORD 分支 → ValidationUtil.isValidPhone() + 密码非空检查

7
业务处理

LoginService.login() → handlePasswordLogin() → getUserByPhone("13546069966") → PUGE_USER_MAP.get() 找到用户 → password.equals(user.getPassword()) 校验通过

8
生成 Token

generateLoginResponse() → UUID.randomUUID() 生成 accessToken + refreshToken → TOKEN_USER_MAP.put(token, userId)

9
返回响应

LoginResponse.success(user, accessToken, refreshToken, 7200) → 构建包含 code/success/message/token/userInfo 的响应对象

10
序列化输出

toJson(response) → 手动拼接 JSON 字符串 → writeResponse(200, jsonString) → HTTP 响应的 OutputStream

11
前端处理

login.js → XHR onreadystatechange → JSON.parse(xhr.responseText) → 保存到 localStorage → 显示 Toast → 1.5 秒后跳转 index.html

💡 追踪技巧：在 IDE 中，从 dragonThermLogin.main() 开始，通过调试器或 System.out.println 逐行追踪一个登录请求的完整路径，这是理解全栈流程的最佳方式。

🧩 七、关键设计模式与架构决策

7.1 项目中实际使用的设计模式

设计模式应用位置说明
单例模式 LoginService, SmsCodeService 在 dragonThermLogin 中作为 static final 单例，HttpServer 中也类似
策略模式 LoginService.login() → switch(loginType) 根据登录类型分发到不同的处理策略 (Password/SMS/WeChat)

Facade 模式 dragonThermLogin 对外静态方法 对外隐藏内部 LoginService 的复杂性

观察者模式 addEventListener 遍布前端代码 DOM 事件监听是观察者模式的经典实现

7.2 为什么要"零依赖"？

设计哲学：这个项目刻意不使用 Spring Boot、Jackson、MyBatis 等框架。

好处： ① 零 JAR 包 — 编译快、启动快
② 理解底层 — 手写 JSON 解析让你知道框架在做什么
③ 部署简单 — 一个 main 方法就跑起来了
④ 学习价值 — 这是理解 Spring Boot 内部原理的绝佳对比材料

8.2 数据生命周期

  • 用户数据：从静态代码块创建 → 注册时新增 → 永不过期（除非手动删除）
  • Token：登录/注册时生成 → 存入 TOKEN_USER_MAP → 理论上 2 小时过期（实际未强制清除）
  • 验证码：发送时创建 → 60 秒后过期 → 校验通过后删除 → 用过的立即清除
⚠️ 生产环境注意：内存存储在服务器重启后会丢失所有数据。生产环境应替换为 MySQL/PostgreSQL + Redis。

🛡️ 十、角色权限系统

10.1 角色定义

角色标识权限
管理员role = "admin"查看所有用户、删除普通用户、访问用户管理面板
普通用户role = "user"登录、查看仪表盘、注册新账号默认为此角色

10.2 权限校验链路

1
前端侧边栏控制

app.js → 读取 localStorage 中的 loginData.userInfo.role → 非 admin 则隐藏"用户管理"菜单项 (display:none)

2
后端 Token 鉴权

HttpServer.authenticateAdmin() → 从 Authorization 头提取 Bearer Token → TOKEN_USER_MAP 查找 userId → USER_ID_MAP 查找用户 → 检查 role == "admin"

3
删除保护（三层）

① 不能删除自己 (adminUser.userId == targetUser.userId)
② 不能删除其他管理员 (targetUser.role == "admin")
③ 前端也做了对应的按钮禁用

10.3 前端权限控制的局限性

⚠️ 注意：前端的 display:none 只是 UI 层面的隐藏，不能替代后端鉴权。
本项目在本地模式下，后端 /api/admin/users 接口有完整的 Token 鉴权 + 角色校验。
但在演示模式下，前端模拟没有做严格的 token 校验——这是因为演示模式本身就是模拟。
